# Zoom into a real letter, then back out into the question

The user asked to replace the previous pushing/wiping animation. After the emotion beat, zoom into an А in the heading “Что влияет на ваше решение”; then zoom back out into “А как это происходит у вас?”.

Wrapped the original heading and influence map in a camera layer. Its transform origin is the actual А in “ваше”, updated at the user's request after they approved the zoom. The camera scales that letter to over viewport height and centers it. At maximum zoom, the composition switches to the first А of the question, using a matching center and glyph height. The question then returns to normal scale and position. Removed the separate decorative letter and rightward push. Total scroll distance remains 1100 px desktop / 900 px mobile.

Transform anchors recover fractional layout coordinates by dividing bounds relative to their camera layer by its current scale. This avoids integer rounding and prevents scaled dimensions from feeding back into the animation during resize. The WebGL renderer now uses the viewer's client dimensions so the CSS camera zoom cannot create an oversized drawing buffer. Static reading order and reduced-motion behavior remain available.

Updated profile-story.cjs verifies the real source letter fills the viewport and is centered, the question appears through decreasing scale, its final layout fits, and reverse scrolling restores the original map. The old pushing animation failed this updated check; the zoom version passed. Screenshots inspected at .preview/profile-letter-zoom.png, profile-question-unzoom.png and profile-question-desktop.png. JS syntax and HTML nesting passed. All seven project browser scripts passed. Independent review found a glyph-size mismatch at the handoff: header and question line boxes had different height/spacing. Added profile-zoom-handoff.cjs, observed it fail, standardized both glyphs to the same font weight, unit line-height and zero letter spacing, and normalized scale by actual font size. The regression then passed on desktop/mobile, together with profile-story.cjs. BFCache verification passed in isolation; its test now waits for an actual subsequent draw instead of assuming a fixed 600 ms frame window under parallel browser load. Final screenshots inspected and local user preview reloaded.
# Smoother scroll follow-up

The user requested softer movement when scrolling rapidly. Increased ScrollTrigger catch-up from 0.3 to 0.7 seconds. Extended the zoom-in from 0.55 to 0.78 timeline units and the zoom-out from 0.65 to 0.77, using gentler easing curves. The zoom starts earlier in the final emotion beat; total scroll distance, overall timeline and the А in “ваше” remain unchanged. Updated handoff sampling times and settling waits in the existing browser checks. Profile scene and glyph-handoff checks pass across desktop/mobile, including reverse scrolling and static fallbacks. Local preview reloaded.
